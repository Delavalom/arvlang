# Phase 3 notes: review round 11

This file continues `16h-phase3-round10.md`. Like `16`, it overrides older plan text. The known limits stay in the "Phase 3: budgets" section of `16-implementation-notes.md`.

Review round 11 (the fifth re-entry) found one Important issue and two Minor ones. The Important one and the second Minor one had one cause, and both were fixed in code. The first Minor one was a documentation error, fixed in `16`. Each test below failed before its fix, for the reason given.

**Fixes:**
- **A denied request costs its text alone (Important).** Round 10 charged each step of canonicalising a request as it went, before the grant check, and for requests that end up denied. So the amount depended on the filesystem outside the grants. An lstat was charged only if every component before it existed and was a directory, and a symlink added Readlink's buffers, its target and a walk of the target. A program holding only `fs_read(G)` could fill `alloc_mb` to an exact level with a string, then call `read_file("<O>/<name>/y")` outside `G`. Whether that failed with "capability denied" or "budget exceeded" told a symlink from a file or a missing name, gave the target's length to within about 7 bytes, and showed which of the target's components existed (`/usr/bin/q` against `/usr/zzz/q`). `spawn ... with [fs_read(...)]` leaked the same way. The comment on `Admit` said a task "cannot tell those apart, nor where a symlink points".
  - `runtime.canonicalFor(path, charge, known)` charges step by step only while every component it looks up is an existing directory. That is what `prepaidCost(path)` assumes: the walk's cost as if every component were an existing directory. It is computed from the text alone, by the same walk run without the OS (`walker.sim`). At the first component that is not an existing directory (missing, a file, a symlink, or an lstat error), the walk checks where that component is. If it is missing or a file inside a grant of the request's kind (`known`, which is `CapSet.Allows`), the walk carries on charging as it goes. Otherwise it charges what is left of `prepaidCost(path)` at once, and from there only counts. `AdmitCharged` charges what the walk cost past `prepaidCost(path)` (only symlinks cost more) only once it has found the request covered, or failing inside a grant.
  - So a denied request is always charged exactly `prepaidCost(path)`. If a missing component, a file or an lstat error inside a grant had stopped the charging, the request could not have been denied. Below a missing component (or a file) nothing is looked up, so the path stays inside the grant, and a `..` there fails inside the grant. A request that meets no deviation pays step by step what the simulation predicts. Every other request pays the rest of the simulation at its first deviation. `CanonicalCharged` (no grants) still charges every step as it goes.
  - Tests: `TestDeniedRequestCostIgnoresOutside` (`arv/runtime/canon_oracle_test.go`): a missing name, a file, a directory, and symlinks to `/x`, to 201- and 202-byte targets, to `/usr/bin/q`, to `/usr/zzz/q` and to a directory, each followed by `/y` and by `/y/deeper/still/f`, for `fs_read` and `fs_write`. Every denial is charged the same. Before the fix the charges ranged from 3301 to 9814 bytes. `TestDeniedRequestStopsAlikeOutside`: a budget one byte short of what a missing name costs stops every name with the charge's error, and one byte more lets every one through to the denial. `TestDeniedSymlinkInGrantCostsItsText`: a symlink inside the grant that leads out is denied at the same cost whatever its target. A mutation that charges a symlink inside a grant step by step makes them cost 4067, 6447 and 8125 bytes. `TestAdmitChargesSymlinksWhenAllowed`: an admitted request through a symlink is still charged at least the heap it used, more than `prepaidCost`, and failing its last charge fails the admit. `TestDenialRevealsNothingOutsideGrants` (`arv/evaluator/denialoracle_unix_test.go`): the reviewer's probe through `read_file` and `spawn ... with`. It bisects the largest padding at which a missing name is still denied. At that padding and one byte more, every other name gives the same outcome.
- **The denial oracle on which outside directories exist (Minor).** The same cause, the same fix: `B/exists/deeper/still/f` and `B/nothere/deeper/still/f` now cost the same, and are covered by the `dirAA` cases above.
- **The `alloc_mb` known limit in `16` (Minor).** Round 10 dropped the uncharged costs that are fixed per call or per request, and it said an fs effect churns a little less than it is charged. That is not true of a nested grant. `16` now gives these numbers, as the reviewer measured them on darwin/arm64:
  - A spawn request that is not an fs one (net, env) is charged 32 bytes plus its scope, about 41 bytes. It churns about 570 bytes: `netScope` runs `ParsePrefix` on a host name, which allocates an error, plus the `seen` map and the `admitted` map of `AttenuateEach`. That is about 14 times the charge. Round 10's `admitted` map added about 20%: for 100,000 distinct net requests, 102 MiB before it and 113 MiB after.
  - Each `http_get` churns about 25 KiB in net/http, including a new client connection, and none of it is charged. So 1000 calls under `alloc_mb: 1` succeed, churning 34 MiB in all.
  - An fs request whose covering grant is nested under a grant of the other kind walks down with `os.Root` one component at a time (`fsopen.go` `step`: Lstat, OpenRoot, Stat), and that walk is not charged. For the 455-level file this churns about 2.5 times what canonicalising it is charged.
  - All three are constant factors per call or per request, as round 9 accepted.

**Changed expectation:** `TestSpawnCapsAreCharged` checked that one request for a 4002-byte path of 2000 components, missing below its first, fits in `alloc_mb: 1`. `t.TempDir()` is under macOS's `/var` symlink, so the request now pays `prepaidCost`, about 5.5 MB. The test now checks the canonical directory under `alloc_mb: 1` and the symlinked one under `alloc_mb: 8`. The 300-copy request is still refused under 1 MiB, with the same 32 MiB heap bound.

**Known limits added:**
- **A request through a symlink, or through a name outside the grants, pays for components that are not there.** It is charged as if every component existed, which is O(depth x length). Most paths have few components, so this costs a few KiB. On macOS a temp path such as `/var/folders/...` or `/tmp/...` goes through a symlink. Grant and request canonical paths to avoid this.
- **What a symlink costs past the prepaid bound is not charged when the request is denied.** The walk does not stop for the budget past that bound, since stopping would say where it stopped. It follows at most 40 symlinks, and Arv code cannot create symlinks, so the cost is bounded by the symlinks the host's filesystem already has. Readlink of a target up to `PATH_MAX`, and an lstat per component of each target, happen once per denied request. A denial ends the task.
- **An admitted request shows, through `alloc_mb`, whether a name outside the grants is a symlink, and about how long its target is.** (Corrected after the post-run review of round 11, 2026-11-11; the owner chose to keep it as a known limit.) A program holding `fs_read(G)` can request `O/<name>/../../<G>/f`. It is admitted both when `O/<name>` is a real directory and when it is a symlink to a sibling directory, so allow against deny cannot tell those apart. But the admitted request is charged what following the symlink cost: on darwin/arm64 a directory cost 4329 bytes (`prepaidCost`) and symlinks 5462, 8347 and 10045 bytes. Bisecting a padding under `alloc_mb: 1` therefore tells the symlink from the directory and gives the target's length. Only symlinks already on the host leak, since Arv code cannot create them. Closing it would mean charging every component outside the grants on an admitted path a fixed worst case per hop, which heavily overcharges ordinary requests (every grant's parents are outside, and `/tmp` and `/var` are symlinks on macOS). The doc comment on `Admit` said a symlink there was denied; it now states this limit. Denied requests are unaffected: a randomized check of 200,000 paths (312,116 denials) charged each one exactly `prepaidCost`.
- **A symlink loop that leaves a grant and comes back counts as failing inside the grant.** It hits the 40-hop limit (ELOOP) on the link inside the grant, so it is charged the walk's excess like an admitted request, and that excess includes the outside link's target length. This is the admitted-request limit above, reached through ELOOP.
- **The uncharged walk of a denied request may act as a timing oracle.** A denied request's walk past `prepaidCost` is not charged, and the number of lstats it makes depends on the symlink chains outside the grants (at most 40 hops), so `timeout_ms` could in principle tell chains apart, through noise.
