## Properties (in process, `llm.Fake`)

- **`TestPropAgentRunsReplayIdentically`** (`arv/p67_prop_test.go`): 200 random programs over every tool kind of `agentTools` (request, file write and read, environment, host effect, randomness and time, a denied tool, a failing tool, an unknown tool), spawned workers with random subsets of the grants, and random limits; the fake follows a random plan with random usage. Each recording is replayed twice with no model host, no grants, another environment and the files gone: byte-identical output and result, no provider call, request, host call or file. Over the 200 cases the logs hold 889 `llm_reserve`, 82 `llm_settle`, 798 `llm`, 52 `http_get`, 41 host and 48 `write_file` records and 515 budget refusals; the test fails if any kind is missing.
- **`TestPropAgentRunsResumeAnywhere`** (`arv/p67_resume_prop_test.go`): 100 random sequential programs (no spawns, no random tool, so the uninterrupted output is fixed), each cut after 3 random lines with the directory as the crash left it, 300 resumes. Each prints the uninterrupted output, sends only the calls whose `llm` record was cut (each a request the uninterrupted run sent), repeats no logged request or host call, and its log replays alike.
- **Mutation check.** Logging no `llm_reserve` (`if true || t.Log() == nil ...` in `reserve`) fails the replay property (a divergence at a racing worker, case 28); skipping `SettleLogged` on a replayed settlement fails the resume property. Both were reverted.

## Leak checks

- `TestP67NoGoroutineOutlivesARacingResume` (`arv/leak_p67_test.go`): three asks racing for `tokens: 14000` (all granted, every settlement fails) and `tokens: 10000` (one refused), recorded four times, resumed after every line: each resume ends well with three lines, its log replays alike, and the goroutine count returns to its baseline after each run.
- `TestP67NoGoroutineOutlivesACancelledRacingResume`: the same logs resumed after every line against a model that never answers, the host cancelling at once, after 1 ms and after 20 ms (a live call in flight, or a task parked in `AwaitReservations`): `Run` returns within 60 s and nothing outlives it.
- Both property tests and both arv fuzz targets check the count after every run.

## Findings

- **A host cancellation can end a run with a budget refusal instead (not a bug; recorded).** In the cancelled-resume test, 6 of 600 resumes returned `budget exceeded: tokens (limit 10000)` (kind `budget`, at the `ask`) instead of the cancellation. A fresh recording does it too (4 to 6 in 300). A task's reservation was refused at the moment the host cancelled, and `match` does not catch an error once its task is cancelled (`evalMatch`, Phase 4), so the refusal became the scope's first failure. A plain run has the same window, only narrower. The test now accepts kind `cancelled` or `budget`, and nothing else (a divergence would fail it).
- **`TestForgedLogsAreRefused`, case "times reversed", was a no-op on a fast run (test flaw, fixed).** It inserted `"began":99999999` before the first `"at":` of the log. A recorded run that ends within a millisecond has every `At` 0, which the line leaves out, so nothing was edited and the replay succeeded: 2 of 5 runs failed under `-race -count=5`, and 36 of 200 recordings of its program had no `"at":`. The case now puts `"began":99999999` on the `http_get` record, after its `At` at any speed (`arv/forge_test.go`); 20 runs pass.
- **The `-race` fork crash recurred** (`16zb`, known limits): `TestP6LogFlagsRefused` reported `signal: segmentation fault` after 4 ms with no output, in one of the `-count=5` runs. A rerun passed.
