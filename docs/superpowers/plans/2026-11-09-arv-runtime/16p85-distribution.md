# Phase 8.5: distribution

Built from `p85-plan-1.md` to `p85-plan-4.md` (design: section 8.5 of `15-phase8-tooling.md`). Nothing was released, pushed or tagged.

## What was built

- **The command is in `cmd/arv`.** The 21 `.go` files of the repository root moved there (`git mv`, so history follows them); the module root holds no Go package. `go install github.com/delavalom/arvlang/cmd/arv@latest` names the binary `arv`. The moved tests read the examples from `../../examples`, and `TestAgentExample` runs from the repository root (`t.Chdir("../..")`), where `examples/agent.arv`'s paths are relative.
- **Every build follows it:** the e2e harness and the Phase 8.4 engine binaries build `cmdArv` (`e2e/harness_test.go`), `bench/run.sh` and `bench/escape/probe.sh` build `./cmd/arv` (their tests in `go test ./bench/...` run them), and `make build` writes `$(BIN)/arv` (`BIN = bin`, a plain assignment: only the command line moves it, an exported `BIN` does not). `make install` is new. Both pass `-X main.commit=` the output of `git rev-parse HEAD`, plus ` (modified)` when `git status --porcelain` prints anything (untracked files count, as they do for the go command's `vcs.modified`), so a build in a git worktree names its commit; outside git the value is empty and `arv version` falls back to the stamp (review round 1).
- **`arv version`** (`cmd/arv/version.go`) prints `arv VERSION`, `commit SHA` (with ` (modified)` for a changed tree) or `commit unknown`, and `GOVERSION GOOS/GOARCH`. Sources in order: the link-time variables `main.version` and `main.commit`; `debug.ReadBuildInfo` (`Main.Version`, `vcs.revision`, `vcs.modified`); the 12-digit commit in a pseudo-version (`go install pkg@<commit>`). `(modified)` is shown only when the commit printed is the stamped one.
- **`.goreleaser.yaml`** (v2): `./cmd/arv` as `arv`, darwin and linux, amd64 and arm64, `CGO_ENABLED=0`, `-trimpath`, `-s -w -X main.version=v{{ .Version }} -X main.commit={{ .FullCommit }}`, tar.gz archives with the README, checksums, draft releases. `dist/` is ignored.

## Known limits

- **A git worktree is not stamped.** The go command (go1.26.2) looks for a `.git` directory; a worktree's `.git` is a file, so a plain `go build` there prints `arv (devel)` and `commit unknown`, even with `-buildvcs=true`. `make build` and `make install` name the commit there (link time) but still print `arv (devel)`. A plain clone is stamped. `go run` never stamps.
- **`TestP85VersionOfSuiteBinary` skips in every worktree run** and in a source copy without `.git`: the suite builds its binary with `go build`, which stamps nothing there. It first compares against HEAD for real in the plain integration checkout, after the merge; the merge agent should check it reports PASS, not SKIP, there.
- **`go install` of a tag prints `commit unknown`:** the module version is all the go command records. `go install` of a commit prints 12 hex digits, not 40.
- **`goreleaser check` was never run**, so a key goreleaser rejects would be found only when someone runs it. The keys used are the documented v2 ones (`version: 2`, `archives.formats`, `snapshot.version_template`).
- **Release builds are CGO-off** and use Go's own DNS resolver; `make e2e` tests the cgo default on macOS. The whole e2e suite passed once on a CGO-off binary (`CGO_ENABLED=0 go test -count=1 ./e2e/`, no `-race`, since `-race` needs cgo; the harness's `go build` inherits the environment).

- **Minor, recorded:** the README restructuring and the 8222bd3 size overrun (Deviations); the suite-binary check runs first on the integration checkout (Known limits).
- **Minor, not attributable to p85:** a reviewer saw the arv binary die by SIGSEGV once (6 ms, empty stderr) in `TestP83SwapRaceCannotEscape/write` on the tree-walker (`ARV_E2E_TAGS=arv_treewalk go test -race -count=1 ./e2e/`), in about 1 of 17 runs under load 20 to 35; it did not recur in 5 single runs or `-count=15`. ## Review round 2

- **Important, fixed (reported twice):** the git fixtures passed the environment's `GIT_*` variables to their children. git exports `GIT_DIR` and `GIT_INDEX_FILE` to its hooks, so a hook running `make test` from a worktree made `freshRepo` reinitialise, stage into and commit "arv e2e" onto the hook's repository (and with only `GIT_INDEX_FILE`, fill its index with entries for blobs that existed only in the deleted temp repository); the go build and `make build` in the fresh repository stamped from it too. `cleanEnv` (`e2e/p85_version_test.go`) drops every `GIT_*` variable from the environment of `git`, of the go build in a fresh repository, of `makeIn`'s make, and of the suite's own build in `TestMain` (so its VCS stamp names the checkout, not `$GIT_DIR`'s). Regression test `TestP85GitFixturesIgnoreGitEnv` (not parallel: it uses `t.Setenv`) points `GIT_DIR` and `GIT_INDEX_FILE` at a decoy repository, runs the bodies of `TestP85VersionFromGit` and `TestP85MakeBuildInWorktree`, and compares the decoy's HEAD, refs, index and config. Before the fix it failed: the decoy's HEAD moved to a new commit, its index changed, and the version check saw `commit "unknown"`. The reviewer's repro (an rsync copy, `GIT_DIR` and `GIT_INDEX_FILE` naming a worktree of a scratch repository, `go test -run TestP85 ./e2e/`) now passes, and the worktree keeps its 2 files, its HEAD and a non-bare main repository.
- **Minor, fixed:** "Measured in p85.4" said `make build` in a worktree prints `commit <SHA> (modified)`; in a clean worktree it prints `commit <SHA>`.
