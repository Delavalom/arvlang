# Phase 3 notes: review round 8

This file continues `16e-phase3-round7.md`. Like `16`, it overrides older plan text. The known limits stay in the "Phase 3: budgets" section of `16-implementation-notes.md`.

Review round 8 found one Critical and four Important issues, all in the same class: memory a program could make the runtime allocate without charging it to `alloc_mb`. Each test below failed before its fix, for the reason given. No finding was Minor.

**Fixes:**
- **`spawn ... with` charges its requests (Critical).** `CapSet.Attenuate` canonicalised every requested capability, uncharged, and the child kept each canonical copy. `Canonical` rebuilt the path with `filepath.Join` for every component, so a 4000-byte path cost about 4 MB (quadratic). The loop never checked the task's context. 300 copies of one long capability made one spawn allocate 1.2 GiB under `alloc_mb: 1`, and 2000 copies overran `timeout_ms: 100` by 19 s. The fixes:
  - `Canonical` appends each component to one buffer, so it is linear in the path's length (`TestCanonicalIsLinear`: under 64 KiB, it was 4.3 MB). `FuzzCanonical` and `FuzzAdmit` ran for 60 s and 45 s on the new code.
  - `CapSet.AttenuateEach` calls back with each request's canonical form before it canonicalises the next one. `spawn` uses the callback to charge `capabilitySize` plus the canonical scope's bytes, and to stop with `spawn in task <id> cancelled: ...` once `Task.Err` reports the task must stop. Tests: `TestSpawnCapsAreCharged` (300 long requests now fail at the `spawn`, and one long or 300 short requests still fit), `TestSpawnCapCostIsExact` (`with [c]` costs 16 + 32 + the canonical scope's length more than `with []`), and `TestSpawnCapsStopWhenCancelled` (2000 requests in a cancelled task allocated 41 MB, now under 1 MiB).
  - The child keeps one copy of each distinct grant, so `[c, c, c]` holds one grant. Every request is still charged.
  - A `DeniedError` lists at most 8 grants (`maxHeldShown`), then `... N more` (`TestDeniedErrorListsFewGrants`). It listed every grant, up to 4096 bytes each.
- **`write_file` does not copy its text (Important).** It converted the text to a new `[]byte` on every call, uncharged: 200 writes of a 1 MB string allocated 193 MiB under `alloc_mb: 1`, and the scope succeeded. `writeIn` now takes a string and calls `File.WriteString`, which does not copy it (`TestWriteFileDoesNotCopyItsText`: under 32 MiB, and the file holds the text).
- **`for ... in` does not preallocate (Important).** It made its result slice with capacity `len(iterable)` before charging any iteration, so a loop that returned at once still allocated 16 bytes per element. The result now grows by `append`, and each iteration's 368-byte charge covers what it appends. `TestForDoesNotPreallocate` checks two cases over a 1,000,000-element array built outside the scope. Five loops that return at once allocated 76 MiB and now stay under 4 MiB. A loop stopped by `alloc_mb: 1` allocated 16 MiB and now also stays under 4 MiB. Through the CLI, the reviewer's `forchurn.arv` under `--alloc-mb 4` went from 371 MB to 52 MB maximum RSS. The baseline that does not loop uses 50 MB.
- **`await` on an array does not preallocate (Important).** It allocated a handle slice for every element before checking element 0. It now checks every element, waits for each task, charges the result array, and only then builds it from the handles. So a failed `await` allocates nothing for the array (`TestAwaitArrayDoesNotPreallocate`: it was 7.8 MB, now under 1 MiB). Errors and their order are unchanged.
- **`http_get` caps redirect URLs (Important).** A redirect's `Location` comes from the server, and nothing limited its length. With a 60,000-byte `Location` of `0xff` bytes, `http_get` followed 10 hops and re-escaped the URL at each one, to 3 times its size. It then failed with a 240 KB `too many redirects` error that quoted the URL. `CheckRedirect` now refuses a redirect whose URL is over `maxURLLen` (8 KiB). A `*url.Error` from `client.Do` now quotes its URL with `quoteClipped`. `TestHTTPGetRefusesLongRedirectURL` checks that the server gets one request, not 10, and that the error is under 2 KiB. `TestHTTPGetRedirectErrorIsClipped` checks that a shorter redirect chain still fails with a clipped error. Through the CLI, the reviewer's 300-task `redir_get.arv` under `--alloc-mb 1` went from 889 MB to 37 MB maximum RSS.

**Kept as is, with the reason:**
- `spawn` checks the task's context after each request is canonicalised, not before the first one. So a cancelled task canonicalises at most one request (at most `MaxScopeLen` bytes and 40 symlink hops) before it stops.
- `DeniedError.Held` still holds a copy of the whole held list (32 bytes per grant) while the error is built. The host chooses the root's grants, and every grant a `spawn` gives was charged at least 32 bytes plus its scope.
- A `for` result can keep up to twice its length in slack from `append`'s growth: 16 bytes per element, which each iteration's charge covers. The result array itself is still charged at 16 bytes per element.
