# Phase 3 notes: review round 9

This file continues `16f-phase3-round8.md`. Like `16`, it overrides older plan text. The known limits stay in the "Phase 3: budgets" section of `16-implementation-notes.md`.

Review round 9 (the third re-entry) found six Important issues and one Minor one. Two of the Important ones were the same issue (`spawn ... with` copying its array). Five were memory the runtime allocated without charging it to `alloc_mb`. One was a race in the Phase 8.3 file code. Each test below failed before its fix, for the reason given. The Minor finding was also fixed.

**Fixes:**
- **`http_get` refuses a long redirect `Location` before net/http parses it, and clips all net/http error text (Important).** Round 8's `CheckRedirect` cap runs only after `req.URL.Parse(loc)` succeeds. A `Location` that does not parse (for example one ending in `%zz`) made `client.Do` fail with `failed to parse Location header %q: parse %q: ...`. That error quotes the whole `Location` twice, so a 60,004-byte `Location` gave a 480,131-byte error. A malformed header line failed with `malformed MIME header line: <the whole line>`, 60,141 bytes. The round-8 note that "an invalid URL or one in a request error is quoted only to 256 bytes" was false for both.
  - The client's transport is now wrapped (`locationCap`). It refuses a 3xx response whose `Location` is over `maxURLLen` before net/http parses it. 20 calls went from 99 MiB to under 20 MiB.
  - `http_get` clips any net/http error text to `clipLen` (`clipped`), not only the URL in a `*url.Error`.
  - Tests: `TestHTTPGetUnparseableLongLocationIsRefused` and `TestHTTPGetMalformedHeaderErrorIsClipped`. `TestHTTPGetRefusesLongRedirectURL` now uses a 3,001-byte `Location`, because a 60,001-byte one no longer reaches `CheckRedirect`. Its escaped form is over the cap, so the test still covers the `CheckRedirect` check.
  - The `http_get` code moved to `httpget.go` to keep `effects.go` under 15 KB.
- **`spawn ... with` takes its requests one at a time (Important, reported twice).** `evalSpawn` copied every element of the `with` array into a `[]runtime.Capability` before `AttenuateEach` charged the first one. For 1,000,000 elements that was 168 MB, uncharged, even in a cancelled task. 100 tasks doing it at once reached a 6.9 GiB heap under `alloc_mb: 1`. The fixes:
  - `CapSet.AttenuateEach(n, req, each)` takes a count and a function that gives the i-th request, and it takes each request only when it gets to it (`TestAttenuateEachDedupesAndCanStop` checks this).
  - `evalSpawn` first checks every element's type, allocating nothing. So a bad element is still found before any request is canonicalised (`TestSpawnWithChecksTypesFirst`).
  - `TestSpawnWithDoesNotPreallocate`: a cancelled spawn went from 168 MB to under 1 MiB. A spawn that `alloc_mb: 1` stops allocated 189 MiB with 1,000,000 requests and 28 MiB with 20,000. It now allocates the same with either.
  - The reviewer's 100-task probe went from 17 GiB in total (6.9 GiB peak) to 714 MiB (231 MiB peak). The baseline that does not spawn is 691 MiB (227 MiB peak).
- **The fs effects charge each grant they stat, and `Covers` copies nothing (Important).** On every call, `read_file` and `write_file` stat each fs grant in the task's lineage (`confiningRoot`). Each stat copies the path. `LineageCaps` copied the lineage, and `Covers` built `c.Scope + "/"` for each grant it checked. None of this was charged. A task holding 1000 grants of about 3000 bytes made 1000 `read_file` calls allocate 11 GiB under `alloc_mb: 64`, and the scope succeeded. The fixes:
  - `Covers` compares in place (`TestCoversAllocatesNothing`). This also removes the cost of requests times held grants from spawn's `Admit`.
  - `Task.Lineage` walks the lineage without copying it.
  - `confiningRoot` charges `statCost` (256) plus the path's bytes before each stat, and stops with the budget's error. So `write_file` is now a `ChargingFunction`.
  - A task whose only covering grant is the target's makes no stat and pays nothing more (`TestFSEffectWithOneGrantIsNotCharged`).
  - `TestFSEffectsChargeTheirGrants`: with 301 grants under `alloc_mb: 8`, the effect now fails at its own call, after a few calls. The reviewer's probe went from 11 GiB to 80 MiB.
  - Charging was chosen over stating fewer grants. A bind mount, or a case-insensitive or normalising file system, can make any grant the same directory as an ancestor of the target, so only identities are safe to compare.
- **`puts` does not copy its text (Important).** `fmt.Fprintln` copied each line into fmt's buffer. fmt does not pool a buffer over 64 KiB, so each call allocated a new one, uncharged. 1000 `puts` of a 1 MB string allocated 961 MiB under `alloc_mb: 1`. The `16c` note that "a string argument prints without a copy" was false until now. A task's `Out` now has `WriteLine`, which writes the line and its newline under one lock with `io.WriteString`. `io.WriteString` does not copy for `*os.File`, `*bytes.Buffer` or `io.Discard`. `runtime.WriteLine` falls back to two `io.WriteString` calls for any other writer. Tests:
  - `TestPutsDoesNotCopyAString`: under 16 MiB, it was 961 MiB.
  - `TestPutsDoesNotCopyItsText`: an array's text is no longer copied a second time. 20 calls went from 38 MiB to under 28 MiB.
  - `TestPutsLinesStayWhole`: 50 tasks print 100 KB lines at once, and no two lines interleave.
- **`write_file` survives a create race (Important, Phase 8.3 code).** `openLeafIn` creates a missing leaf with `O_EXCL`. If another writer creates the leaf between the lstat and the open, the open fails with EEXIST. `write_file` returned that error, although nothing unsafe had happened. It now tries once more: the leaf exists, so it is opened without `O_CREATE` and checked with `SameFile`. A symlink planted there is still refused. Tests: `TestWriteFileCreateRace` (deterministic, through `beforeStep`) and `TestWriteFileConcurrentCreate` (100 tasks, with a leak check).
- **`readCapped` sizes its first chunk (Minor).** It made a 32 KiB chunk before its first read. Each `read_file` of a 2-byte file allocated that whole chunk and charged 2 bytes. It now takes a size hint: the file's `Stat` size, or the response's `Content-Length`. Its first chunk is `hint + 1` bytes when that is smaller than 32 KiB. A wrong hint only costs another chunk (`TestReadCappedWrongHint`). In `TestReadSmallFileAllocatesLittle`, 1000 reads went from 36 MiB to 5.5 MiB.

**Kept as is, with the reason:**
- Checking and opening a path still allocates about 5 KiB per fs effect call, uncharged. Of that, about 3.3 KiB is `Admit`'s canonicalisation, which makes one lstat per component, and the rest is `os.Root`. Each spawn request is also canonicalised, about 3 KiB, and is charged only 32 bytes plus its canonical scope. Each amount is fixed per call or per request, not proportional to data, so it is listed as a known limit in `16`.
- `AttenuateEach`'s `seen` map and result slice are not charged. They grow by one entry per distinct charged request, so they add only a constant factor.
- `net/http` still builds its error text (a malformed header line, up to `maxHeaderBytes`) before `http_get` clips it. That copy is short-lived and capped at 64 KiB, like the headers themselves.
