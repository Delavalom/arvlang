# Phase 3 notes: review round 7

This file continues `16c-phase3-notes.md` (review rounds 1-6 and the mutation tables), which is close to the size limit. Like `16`, it overrides older plan text. The known limits stay in the "Phase 3: budgets" section of `16-implementation-notes.md`.

Review round 7 changed the following. Each test below failed before its fix, for the reason given.

**Fixes:**
- **Capability values are charged, and scopes are capped.** `allocSize` returned 0 for a capability, but a capability keeps its scope alive, and `net(s)` builds a new string for it (lower case, normalised port). A loop of `net(s)` over a 1 MB host kept 287 MiB alive under `alloc_mb: 1`, and the scope succeeded. A capability now costs `capabilitySize` (32) plus its scope's bytes (`TestCapabilityValuesAreCharged`, exact at the limit and one byte under). `runtime.Literal` refuses a scope over `runtime.MaxScopeLen` (4096 bytes, Linux's `PATH_MAX`) before anything copies it, and `normHost` refuses a host name over 253 bytes (the DNS limit, without `*.` or a trailing dot). The fs and env builtins check the length before `absPath` copies the argument. `TestCapabilityScopeLengthIsCapped`, `TestNetLoopOverHugeHostAllocatesLittle` and `TestScopeLengthCaps` (runtime) cover this.
- **Error text stays small.** Error values are not charged, but `http_get` quoted its whole URL with `%q` (4 bytes per control byte), and the fs and env builtins copied and quoted their argument. 200 tasks under `alloc_mb: 1` with a 1 MB argument allocated 5.3 GiB (`http_get`), 3.4 GiB (`read_file`) and 0.6 GiB (`getenv`), and one CLI run reached 2 GB RSS. `http_get` now refuses a URL over 8 KiB (`maxURLLen`, about what nginx and Apache accept) before parsing it, and quotes an invalid URL only to 256 bytes plus its length (`quoteClipped`). The scope cap above covers `read_file`, `write_file`, `getenv` and the constructors. `TestErrorTextStaysBounded` checks each message and bounds 200 tasks under 32 MiB. `TestInvalidURLErrorIsClipped` and `TestHTTPGetAcceptsLongURLUnderCap` cover the edges.
- **`push` charges before it copies.** It was a plain `Fn`, charged after it returned, so a refused push onto a 1,000,000-element array built outside the scope allocated 16 MB under `alloc_mb: 1`. It is now a `Charging` builtin that charges `16 * (len + 1)` first, as a concatenation is charged (`TestPushOverLimitBuildsNothing`). Its cost is unchanged (`TestPushCostsItsResult`). This also closes the Minor finding about `push`.
- **`readCapped` keeps no slack.** `strings.Builder.Grow(len)` allocates `2*cap + len`, so the buffer tripled on each growth, and the string kept all of it, uncharged: a held 9 MiB result kept about 2.3 times its size alive. The old comment ("double") and the old note ("at most twice what it has charged") were wrong. It now reads into 32 KiB chunks and copies them once into a string of exactly the result's size. `TestReadCappedKeepsOnlyItsResult` bounds what 4 held reads keep alive (at most 9/8 of their bytes plus 1 MiB) and allocate (at most 2.5 times), from 100 KiB to 9 MiB.
- **A negative limit is an error.** `newPool`, `level` and `newScope` read any limit of 0 or less as "no limit", so a host passing `Steps: -1` got an unlimited run. `runtime.Limits.Validate` refuses any negative field, and `arv.Run` returns its error and runs nothing (`TestNegativeLimitsAreRefused`). The CLI and scope options already refused 0 or less.

**Tests only:**
- `wantBareAllocError` now takes the expected position and checks it: the `read_file` or `http_get` call, the `s + s` operator, or, for a task spawned straight onto a builtin call (`spawn read_file(..)`), the `spawn`. The single-call read tests now call `settled`.
- `TestHTTP2HeaderListIsCapped` fetches over HTTP/2 with TLS through `transportFor`, checks the small response is HTTP/2, and checks a 1 MiB header list is refused. With `MaxResponseHeaderBytes` unset it fails, so the round-6 claim that the cap also bounds the HTTP/2 header list is now pinned.
