## Recorded, not changed

- **The `--manifest` pre-check runs before `--timeout` starts.** It parses the file and walks it once. Each step is linear in the file's size, or bounded per call (folding by its 1 MiB budget, `least` by name length and prefix count). It does no I/O except for the header comparison below. It takes a few hundredths of a second for a 350 KB script. **Corrected in round 2:** this was true only for a short header. `Outside` compared every site with every header line (O(H x S)), so 16000 header lines and 16000 needs took 8 to 15 s. Round 2 indexes the header, and records the lstat cost of the comparison with measured numbers: see [`16p81c`](16p81c-check-round2.md).
- **With a header, `arv check` lstats paths the program names** (plan deviation 5). To compare a needed path with the header, `Outside` resolves it through `CapSet.Admit` as `--allow` would (lstat, readlink). Those paths come from the program. On macOS, an lstat under the autofs mount `/net/<host>/...` makes the automounter contact that host, so checking a file whose header grants `fs_read=/net` and that names `/net/some-host.example/x` can reach a host the program chose. Without a header, `arv check` reads only the file. The guarantee "never executes effects" means no Arv effect runs; the lstat is filesystem metadata, as for `--allow`. Not reproduced here, since that would contact a host.
- **`uptime.arv`'s printed set is not its README flags.** `15-phase8-tooling.md` §8.1 accepts the phase when "for every file in `examples/`, the printed set is exactly the flags its README line uses". That holds for `fanout.arv`. For `uptime.arv`, `arv check` prints `fs_read=targets.txt` and `fs_write=out/report.json`, plus notes for `http_get(url)` and `net(host)`; its line uses `fs_write=out` and `net=127.0.0.1:PORT`. Plan deviation 1 records the reason, and `TestP81ExamplesCheck` pins the actual output. **Owner sign-off needed** on this amendment to the acceptance criterion.
