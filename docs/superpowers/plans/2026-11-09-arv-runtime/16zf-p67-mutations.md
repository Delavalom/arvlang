# Phase 6x7: mutation check, round 1

This file continues [`16ze-p67-e2e.md`](16ze-p67-e2e.md). The run was on 2026-11-12, on `phase/p67` at `0d3a07f`.

**Method.** Each mutation was one exact-text substitution in one runtime file (the pattern had to match exactly once). The tree was then built and tested with `go test -count=1 -timeout 600s ./...`, which covers the CLI package, every `arv` package, `e2e` through the binary, and `examples/host`. Afterwards the file was restored with `git checkout --`, and `git status` was checked to be clean before the next mutation. No mutation was committed. Load average was between 10 and 30, with about 10 GB free. M01 and M25 were also checked with targeted runs (see below).

**Result: 25 mutations, 23 caught, 2 not caught** (M01 and M25). 15 of the caught mutations were caught by the e2e suite as well as by unit tests. M10 and M11 also hung the `arv` package until the 10-minute timeout, and M21 hung an e2e test for 90 s.

**Baseline failures that no mutation caused.** `TestResumedQuietChecksSeeDeadlines` and `TestResumedQuietChildSeesItsDeadline` (`arv/resume_deadline_test.go`, Phase 6) failed on the unmutated tree in the full `go test ./...` without `-race`. Both pass alone (`-count=3`) and under `-race`. They failed in almost every mutation run, so they were left out when deciding whether a mutation was caught. They look like timing flaws in the tests under load, not Arv bugs, but this round did not investigate further.

**A scratchpad collision (recovered).** Partway through the first batch, another phase's checker overwrote this run's driver script. M17 ran partly under that script, and M18 to M26 did not run. The tree was restored and checked clean, the script was rewritten (it now refuses to run off `phase/p67`), and M17 to M26 were run again from scratch. The table has only those reruns.

## Not caught

- **M01: a replay that has a model host would send its calls.** The suite replays with no host, so `liveProvider` fails before `Complete` is called and the mutant sends nothing. `TestReplayOfAChangedPromptDiverges` passes a host, but that run diverges first. A throwaway probe (recorded, replayed with `Options{Replay: l, LLM: host}`, never committed) printed the recorded output under the mutant. The fake then saw 2 calls where the recording made 1, and on the unmutated tree it saw 1. The CLI does give a replay a host: `runCLI` sets `opts.LLM = hostLLM()` before the log flags are applied, so `ANTHROPIC_API_KEY=... arv run --replay` has a live provider. The guarantee holds on the current tree; it is the check that is missing. **Test gap:** replay with a live `llm.Host` (in process), and through the binary with `ANTHROPIC_API_KEY` set, and assert zero requests.
- **M25: nothing catches a cancelled resume that keeps waiting in `AwaitReservations`.** Even with `-count=3`, `TestP67NoGoroutineOutlivesACancelledRacingResume`, `TestResumeWaitsForLoggedReservations`, `FuzzForgedAgentResume` (seeds) and the other leak tests passed. Under a host cancellation, the replayed tasks still act out their logged reservations from the log, so `models.done` closes anyway, and on an honest log the mutant is close to equivalent. It would matter only if a logged reservation can never be acted out, as in a forged log or a replayed task blocked on a live one. The stall watcher may cover that case, but no test was found that shows it. **Possible test:** a resume whose log holds a reservation for a task that never reaches it, cancelled by the host, which must end within a bound.

## Round 2: the two gaps closed

Each new test was run against its mutant, applied by hand and then restored with `git checkout --`; each fails under the mutant and passes without it.

- **M01, now caught.** `TestReplayWithALiveModelHostSendsNothing` and `TestReplayOfRacingAsksWithALiveHostSendsNothing` (`arv/replay_live_host_test.go`) replay with the recording's `llm.Host` (and no grants: a replay takes its grants from the log). Under the mutant the fake saw 9 extra calls for the agent run and 2 for the racing asks. `TestP67ReplayWithTheKeySetIsOffline` (`e2e/p67_replay_key_test.go`) replays through the binary with `ANTHROPIC_API_KEY` set and `ARV_ANTHROPIC_URL` pointing at the fake; under the mutant the fake saw 3 extra requests, while stdout still matched.
- **M25, now caught.** `TestResumeWithAReservationNoTaskActsOutEnds` (`arv/resume_phantom_reserve_test.go`) resumes a forged log that keeps the root's `llm_model` record and moves its `llm_reserve` record to a task the program never spawns (`root/7`). The root's live reservation then waits in `AwaitReservations` for a reservation nothing will act out. The resume must end, with a divergence from the stall watcher when nobody cancels it and with a cancellation or divergence when the host cancels it after 0, 1 ms or 50 ms, and leave no goroutine behind. Under the mutant both the uncancelled case and the 50 ms case hung until the test's bound.

**A test flaw found by the pre-commit run (not fixed here).** `TestForgedLogsAreRefused` (`arv/forge_test.go`) failed once in the pre-commit `go test -race ./...` on the unmutated tree. It then passed with `-race -count=40` alone and in a second `-race` run of `./arv`. The cause is likely its case "times reversed". That case inserts `"began":99999999` before `"kind"`, but the encoder writes `began` after `kind`. If the `http_get` begins 1 ms or more after the run starts, the line already holds a nonzero `began` after `kind`. `encoding/json` keeps the last duplicate key, so the forged value is dropped, the times stay in order, and the expected "out of order" error never comes. The runtime check (`rec.At < rec.Began`, `logfile.go`) is not at fault. **Fix:** replace the record's own `began` field, or insert the forged one after it, instead of putting it before `kind`.
